# 皇加布業 ERP 進銷存模組 Phase 1 — 流程原型

RORICA TEXTILE CO., LTD. 進銷存模組的**流程原型（Prototype）**，用於在進入開發前確認單據流程、欄位設計與各路徑分支。

> **這不是已上線的系統。** 沒有後端資料庫、沒有登入驗證，畫面上所有資料皆為模擬資料。

## 線上試用

（部署後補上網址）

第一次打開建議照著下方「導覽路線」走一遍，較容易看懂整體流程。

## 使用前必讀

| 事項 | 說明 |
|---|---|
| 資料是假的 | 客戶、廠商、商品、單據全為模擬資料，與實際營運資料無關 |
| 資料不共享 | 沒有後端，您建立／修改的單據**只存在您自己的瀏覽器分頁**；同事開同一個網址看不到您建的單據 |
| 資料會重置 | 關閉分頁即回到預設展示資料；亦可按右上角「重置模擬資料」隨時清空測試內容 |
| 建議裝置 | 請用**電腦瀏覽器**操作，單據表格較寬，手機版面會過於擁擠 |

## 導覽路線（建議照順序點一遍）

完整走過一張訂單從接單到出貨的八張單據：

1. **表1 包裝通知單** — 建立新單，明細指定商品與數量。系統自動判斷有無現貨
   - 有現貨 → 直接建立庫存預留與表8出貨單草稿
   - 無現貨 → 自動建立表2訂購單草稿
2. **表2 訂購單** — 補齊廠商、交期、單價後送出（待簽回）→ 確認簽回
   - 類型「胚布」＋填入染整廠 → 觸發表4染整單
   - 類型「成品」→ 大貨樣確認送樣通過後觸發表6入庫單
3. **表3 打色通知單** — 查無歷史色號時系統自動開立，委託染整廠打色；色樣編號回填後回寫染單
4. **表4 染單** — 確認建單後委外加工；大貨樣通過即結案，並依明細有無「加工方法」分岔至表5或表6
5. **表5 二次加工單** — 指定加工廠後發包，結案時建立表6入庫單
6. **表6 入庫單** — 登錄實際入庫捲數與碼數，複核後確認入庫
7. **表7 布疋條碼標籤** — 入庫確認時每捲自動產生一張，可分割布卷
8. **表8 出貨單** — 確認出貨後扣減庫存，全部明細出貨完成即回頭結案表1

各單據詳情頁右上角皆有「版面預覽」與「列印」，可檢視實際紙本列印格式。

## Phase 1 已實作範圍

- 表1–表8 完整單據流程與所有分支（有現貨／無現貨、接疋建議、成品／胚布、委外染整／純採購、二次加工）
- 主號貫穿編號（`ORD-YYYYMMDD-NNN` 及其子序號 `-P/-C/-D/-X/-R/-S`）
- 三段式庫存追蹤（待染／指染／成品）、庫存預留與 14 天效期
- 接疋拼接建議（系統建議、人工確認）、整捲＋裁切配貨、布卷分割與長度異動紀錄
- 生效後 7 個工作天自動凍結、訂購單 2 日未簽回自動標記逾期
- 四大主檔（客戶／商品／廠商／帳號）
- 對外單據列印格式（表2／表3／表4／表5／表7／表8），表7 為可掃描的 Code 128 條碼

## 尚未實作（屬後端階段）

- 登入驗證與欄位層級權限控管（畫面上的權限矩陣為示範架構）
- 真實 OCR 辨識（表6 目前為手動輸入＋信心度標記的模擬介面）
- 稽核軌跡的實際欄位異動比對
- 並發編輯鎖定（15 分鐘逾時）
- 排程觸發的通知推播（目前為依現有資料即時運算的展示用通知）
- 表1 嘜頭列印格式（待客戶提供實際版面）

## 開發

需要 Node.js 22 以上。

```bash
npm install
npm run dev      # 本機開發
npm run build    # 產出靜態檔至 dist/
npm run preview  # 預覽 build 結果
npm run lint
```

技術：React 19 + TypeScript + Vite、TanStack Query/Table、react-hook-form + zod、Tailwind CSS v4、radix-ui。

資料層位於 `src/mocks/`：`data.ts` 為種子資料與分頁快照、`api.ts` 為讀取、`mutations.ts` 為所有業務規則與單據流轉邏輯。
